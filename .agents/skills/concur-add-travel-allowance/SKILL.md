# Add Concur Travel Allowance

Add meal allowances to an existing expense report using the shared browser page. Verified in the English Concur UI; fields and defaults can vary by company configuration.

## Boundaries

- Never click **Submit Report**. Only the user may submit a report.
- Do not invent provided meals from every hotel night, or enter missing journey times from assumptions.

## Gather Inputs First

Read [profile/profile.md](../../../profile/profile.md) and [knowledge/expenses.md](../../../knowledge/expenses.md) from the workspace. Confirm the intended existing report; do not create a second report.

Reuse information already supplied by the user or present in the profile. Ask only for missing or conflicting details before editing:

- Outbound leg: origin city, departure date and time, destination city, arrival date and time.
- Business-site address: street, city, and postal code. This is the location visited for business, not automatically the hotel or station.
- Return leg: departure city, date and time, home-arrival city, date and time. Home departure and return times alone are not enough for the wizard.
- Employer-provided breakfast, lunch, and dinner, identified by exact calendar date.
- A user-supplied business purpose or factual comment for each generated allowance. These entries require **Business Purpose / Comment**, even when generated by Concur.
- Any other confirmed adjustments requested by the user; do not assume overnight allowances are required.

Use the date format shown in the UI, i.e. `DD.MM.YYYY` and 24-hour times such as `07:00` and `15:50`.

## Browser Procedure

### 1. Open Travel Allowance

1. Read the current page and open **Travel Allowance** (German: **Tagespauschalen**). Read any menu it opens and select the applicable itinerary action.
2. Read the resulting wizard. It may navigate the same page to the legacy `Expense/Client/XpresswayTA.asp` UI; keep using the current page ID and refresh element references.
3. Look for existing assigned or available itineraries before creating duplicates. Use the intended itinerary if it already belongs to this report; ask before reassigning one from elsewhere.

### 2. Enter and Save Journey Legs

The wizard has three stages: **Create New Itinerary / Edit Itinerary**, **Available Itineraries**, and **Expenses & Adjustments**.

1. Check **Itinerary Name**; it may be prefilled from the report name.
2. Fill the outbound **Departure City**, departure **Date** and **Time**, **Arrival City**, business-site **Address**, and arrival **Date** and **Time**. Select the matching city suggestion where required, rather than leaving unconfirmed search text.
3. Click the leg's **Save**. Wait for the saved journey row to appear and verify both endpoints and times before continuing.
4. The new-stop form then prefills the return cities and home address. Verify these values; automatic completion is not proof they are correct.
5. Fill the return departure and arrival dates and times, correct any address or city mismatch, and click **Save** again.
6. Verify both saved rows. An empty new-stop form after saving is normal; do not add a third leg unless the actual itinerary needs one.
7. Click **Next >>** to **Available Itineraries**. Confirm the intended itinerary is listed under **Assigned Itineraries**, then **Next >>** to **Expenses & Adjustments**.

### 3. Apply Meal Adjustments

1. Check that the daily rows cover the intended trip dates and locations before changing anything.
2. Mark **Breakfast Provided**, **Lunch Provided**, or **Dinner Provided** only on confirmed dates. Leave **Exclude** and **Overnight** unchanged unless the user's facts require those adjustments.
3. Read each recalculated daily amount and check the total. Let Concur calculate the allowance.
4. Click **Create Expenses** once. Verify the resulting **Daily Allowances** entries in the report before retrying any apparently slow action, to avoid duplicates.

### 4. Complete Generated Expenses

1. Open **View Alerts** after expense generation. A generated allowance may have a warn about **Missing required field: Business Purpose / Comment**.
2. Open each affected daily allowance, fill its **Business Purpose / Comment**, and click **Save Expense**. 
3. Verify the saved entry before opening the next one.

### 5. Verify and Stop

- Confirm the expense count, dates, daily amounts, and total match the itinerary and meal adjustments.
- Confirm the selected meals are correct and expense-level errors have cleared; report unresolved errors honestly.

## Efficiency and Troubleshooting

- **Refresh after saves and toggles.** This UI rerenders rows and changes `e...` references. Never reuse a stale breakfast-cell reference for the next day.
- **Use focused browser reads.** Prefer `read_page`, `click_element`, and `type_in_page`. Read the relevant part of a saved snapshot instead of repeatedly reading console warnings and navigation chrome.
- **Legacy checkboxes may appear as blank cells.** Align the current visible headers with each date row. Some DOM cells are hidden, so raw child indexes can identify the wrong column. If the snapshot omits checked state, use a small read-only `run_playwright_code` inspection of visible cells and control classes; avoid dumping full HTML.
- **Check state before toggling.** In the tested UI, a custom checkbox uses `x-grid3-check-col-on` when selected. Its `ext-gen...` identifiers are generated, not stable selectors. Discover the current breakfast column, click its current cell reference only if needed, then verify the control state and recalculated amount.
